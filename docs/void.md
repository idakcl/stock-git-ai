# 单据作废（void）

> 适用对象：**销售单**与**采购单**。作废的同时把该单的**收款单（`SK-`）/ 付款单（`FK-`）一起作废**。
> 入口：销售/采购列表操作列的「作废」按钮；接口：`POST /api/voids`。

## 为什么是「作废」而不是「删除」

删除会把单据从数组里抹掉：凭证还挂在 `receipts.json` / `payment-vouchers.json` 里，
资金台账出现一张找不到主人的 `SK-`，库存与历史价也解释不清「这 50 件为什么进过又没了」。
作废保留单据与凭证（可查、可审计、单号不复用），但业务上当作没发生过：

| 维度 | 作废后的效果 | 实现位置 |
|---|---|---|
| 单据 | `status: '作废'`，金额与明细原样保留 | `applyVoidOperation` |
| 应收 / 应付 | 归零（`grossOf` 返回 0） | `src/utils/account.js` |
| 实收 / 实付 | 不再计入（`receivedSumOf` / `paidSumOf` 返回 0） | 同上 |
| 库存 / 历史价 / 成本价 | 派生时跳过该单，等价于回滚 | `derive()` / `rebuildStock()` |
| 收款单 / 付款单 | `status: '作废'`，编号与金额保留，`voidOf` 指回被作废的单 | `applyVoidOperation` |
| 预存 / 预付流水 | 本单产生的抵扣、超收转存流水一并撤掉；用了预付款的余额原样退回 | 同上 |
| 订单来源单 | 退回「未过账」，并摘掉已作废的订金记录 | 同上 |

**不可恢复**：没有「取消作废」。需要重开就再录一张——「作废」永远是账实一致的分界线，
不会出现「作废又恢复、凭证废了又活」的中间态。

## 接口

```json
POST /api/voids
{ "kind": "sale", "id": "X202610280930000001", "reason": "客户取消" }
{ "kind": "purchase", "id": "C202610280930000001" }
```

- `kind` 省略时按 `sale` 处理；`reason` 可选，最长 200 字。
- 成功：`{ ok: true, code, vouchers: ["SK-20261028-0001"], unpostedOrderId?, commit }`
  - `vouchers` 是被同步作废的凭证编号，前端提示里直接列出；
  - `unpostedOrderId` 非空表示来源订单已退回未过账；
  - 重复作废不报错，返回 `{ ok: true, duplicate: true, vouchers }` 且**不再产生新提交**（幂等）。
- 失败：`404` 单据不存在；`409` 被闸门拦下（见下）。错误响应是 `{"error":"中文原因"}`。

事务语义与退款/订单一致（`api/tx.js`）：读一份固定快照 → 纯函数 `applyVoidOperation` 算新状态 →
**一次提交**发布单据、凭证、库存、客户/供应商、订单与日志。写失败不重放，避免用旧数据覆盖。

## 闸门（必须先处理，不能替用户猜）

1. **有变更单**：该单存在 `sourceOrderId === 本单号` 的退货/补差单 → `409`。
   子单金额基于原单算出，原单一作废，子单就成了无源之水。
2. **有退货核销记录**：`settlements` 非空 → `409`。退款是双边核销，原单作废会让另一半悬空。
3. **凭证是多单合并的**：一张 `SK-`/`FK-` 的 `items[]` 还指向别的单据 → `409`。
   整张废掉会连带别家的收款记录，请先到「收付款单」里拆开。
   例外：订单订金凭证的 `items[].orderId` 指向的是**本单的来源订单**（`fromOrderId`），
   它属于本单自己，不算共享。

## 数据结构变化

销售单 / 采购单新增：

```json
{
  "status": "作废",
  "voidedAt": "2026-10-30T09:00:00.000Z",
  "voidedReason": "客户取消",
  "voidedVouchers": ["SK-20261028-0001"]
}
```

资金凭证新增：

```json
{ "code": "SK-20261028-0001", "status": "作废", "voidedAt": "…", "voidedReason": "客户取消", "voidOf": "X202610280930000001" }
```

- `status` 与 `voided: true` 等价（`isVoided()` 同时认这两种写法，兼容早期手工标记的数据）。
- 统计口径：**作废单不进任何合计**。列表页仍会列出（带「作废」标签）以便追溯，
  但应收/应付、实收/实付、库存、历史价、来往账、看板、报表、收付款单累计都按 0 / 跳过处理。
- 脚本直读数据仓时，请先过滤 `status === '作废'` 或 `voided === true`，再按「账务公式」重算。

## 前端行为

- **列表页**：单号旁打「作废」标签；编辑 / 收款（付款）/ 作废按钮禁用；删除仍可用于清理作废单。
  结算状态列不再显示「结清/挂账」，避免与 0 应收混淆。
- **详情页**：顶部黄色提示条写明作废时间、原因与后果；编辑 / 删除 / 退货 / 记录收款（付款）/ 改结清全部隐藏或禁用。
- **资金单据页**：作废凭证带「作废」标签，抽屉顶部有提示条；`收款单累计` / `付款单累计` / 筛选合计都不含作废凭证。
- **收款/付款弹窗**：作废单没有「收款」按钮，无法再从界面给它记一笔钱。

## 常见问题

- **作废后还能改吗？** 不能。作废是终态；要改请重新开单。
- **作废后单号会复用吗？** 不会。单号按日期流水递增，作废单永久占用原号。
- **作废一张合并收款的单怎么办？** 先用「收付款单」页面把那张凭证拆成两张（或先删掉重记），再作废。
- **作废后预存款为什么变多了？** 本单用预存款抵扣过；作废即撤销抵扣，余额回到账上，这是对的。
